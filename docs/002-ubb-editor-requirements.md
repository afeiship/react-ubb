## 文档信息

| 项目 | 内容 |
| --- | --- |
| 版本 | v0.2 |
| 日期 | 2026-11-13 |
| 状态 | 待评审 |
| 作者 | 产品 / 前端共同维护 |

## 1. 概述

### 1.1 文档目的

定义一个基于 React 的 UBB 代码编辑器，用最少的标签能力（加粗、斜体、字体颜色）替代富文本编辑器，使系统在不需要富文本的场景下仍能满足基础排版诉求，同时保证存储结构始终是纯文本。

### 1.2 背景与问题

现状：论坛、工单、评论、活动文案等场景引入富文本编辑器（Quill / Slate / Draft.js / wangEditor）后，普遍出现以下问题：

1. 产出的是 HTML 或 Delta 结构，后端需存 HTML，前端需渲染 HTML，XSS 面扩大，必须额外做 sanitize。
2. 粘贴内容带外部样式（字体、字号、行高、背景色），清洗成本高且结果不可控。
3. 富文本编辑器体积大、光标与选区行为复杂，移动端 WebView 兼容性差。
4. 业务实际只需要极少量强调能力，投入产出比低。

### 1.3 结论

用 UBB 标签作为样式唯一载体，编辑器本质是"纯文本 + 方括号标签"，所见即所得通过实时预览实现，产出与存储始终是 `string`。

## 2. 术语定义

| 术语 | 定义 |
| --- | --- |
| UBB | 以 `[b][/b]` 这类方括号标签标记样式的轻量标记语言，源文本本身可读 |
| 源文本 | 用户输入并最终保存的内容，包含标签 |
| 可见文本 | 渲染后用户实际看到的文字，不含标签 |
| 渲染器 | 将源文本解析为安全 React 元素（AST）的模块 |
| 包裹 | 在选区前后插入成对标签 |
| 解包 | 移除选区外层已有的成对标签 |
| 插空 | 业务自定义标签 `[blank]...[/blank]`，用于标记填空位，经 customTags 注册启用（见 FR-38） |

## 3. 目标与非目标

### 3.1 目标

| 编号 | 目标 |

## 5. 功能需求

### 5.1 编辑器形态

| 编号 | 需求 |
| --- | --- |
| FR-01 | 输入层使用原生 `textarea`，不使用 `contenteditable`。理由：contenteditable 是富文本入口，光标、选区、撤销栈、输入法组合态均不可控，且极易引入 HTML。 |
| FR-02 | 布局默认左右双栏（左源文本 / 右预览），支持三种布局：仅编辑、左右分栏、上下分栏；另提供全屏模式。组件自带"编辑 / 预览"双模式切换（`mode`：'edit' | 'preview'）：预览模式下隐藏编辑区，整区只读渲染；工具栏右侧提供切换按钮；`mode` 可受控传入，不传时由组件内部维护。 |
| FR-03 | 工具栏固定于编辑区上方，内置按钮：加粗、斜体、颜色、插空；customTags 注册的业务标签按注册顺序追加；可选按钮：清除当前样式、清空内容。 |

### 5.2 标签规范

| 编号 | 需求 |
| --- | --- |
| FR-04 | 内置合法标签集合（唯一白名单）如下；业务自定义标签经 customTags 注册后同样进入白名单（见 5.10）： |

| 标签 | 样式 |
| --- | --- |
| `[b]...[/b]` | 加粗 |
| `[i]...[/i]` | 斜体 |
| `[color=#RRGGBB]...[/color]` | 字体颜色 |
| `[blank]...[/blank]` | 插空（业务自定义，经 customTags 注册） |

| 编号 | 需求 |
| --- | --- |
| FR-05 | 颜色值仅接受 6 位或 3 位十六进制；可选接受 `rgb(r,g,b)`。其他写法（如 `[color=red]`）视为非法，不猜测、不自动纠正，预览按无颜色降级处理，并置非法标记。 |
| FR-06 | 支持嵌套，但必须严格闭合。对 `[b][i]x[/b][/i]` 这类交错闭合，渲染器按就近闭合修复，修复过程不得吞字、不得改变可见文本顺序。 |
| FR-07 | 标签名大小写不敏感（`[B]` 等价 `[b]`），输出统一小写。 |
| FR-08 | 白名单之外的方括号内容（如 `[foo]`、`[img]`）一律按普通文本处理，不解析、不报错，避免与业务已有文本冲突。 |
| FR-09 | 字面输入 `[b]` 需有转义约定，方案见 Q1。 |

### 5.3 选区包裹与样式切换（核心交互）

| 编号 | 需求 |
| --- | --- |
| FR-10 | 选中文本后点击"加粗"，在选区前后插入 `[b]` 与 `[/b]`，操作后保持选区，用户可继续叠加斜体或颜色。 |
| FR-11 | 未选中文本点击"加粗"，插入 `[b][/b]`，光标置于两标签之间，随后输入的内容自动落在加粗区间内。 |
| FR-12 | 幂等切换：若选区已完整位于某 `[b]...[/b]` 内部，再次点击执行解包；若选区跨越标签边界（不完整），执行包裹而非解包。 |
| FR-13 | 快捷键：Ctrl/Cmd+B 加粗，Ctrl/Cmd+I 斜体，仅在编辑器聚焦时拦截，避免影响页面其他输入框。 |
| FR-14 | 所有插入操作必须正确恢复光标 / 选区位置，操作后编辑器保持聚焦。 |
| FR-15 | 撤销栈：优先走浏览器原生撤销（textarea + `execCommand('insertText')` 或 `setRangeText` 可保留原生 undo）；若改为 setState 拼接字符串，需自建 undo/redo 栈（至少 50 步），绑定 Ctrl+Z / Ctrl+Shift+Z，并保证与原生行为不冲突。技术取舍见 7.2。 |

### 5.4 颜色

| 编号 | 需求 |
| --- | --- |
| FR-16 | 点击颜色按钮弹出取色面板，面板包含：预设色板（建议 12-20 个常用色，与产品主题一致）、自定义取色区、十六进制输入框、最近使用（最多 8 个）。 |
| FR-17 | 选中文本后选色，包裹为 `[color=#hex]...[/color]`；未选中时插入空标签，光标置于标签中间。 |
| FR-18 | 若选区已位于某 color 标签内，选新颜色直接替换原标签颜色值，不产生双层嵌套 color。 |
| FR-19 | 取色面板支持键盘操作与 Esc 关闭，点击遮罩关闭。 |
| FR-20 | 取色实现二选一：a) 复用 react-color（成熟，但需按需引入单组件以控体积）；b) 自研轻量色板 + 原生 `input[type=color]`（零依赖）。决策依据：包体积预算见 NFR-03。 |

### 5.5 预览与解析

| 编号 | 需求 |
| --- | --- |
| FR-21 | 预览以 React 元素方式渲染，禁止 innerHTML。 |
| FR-22 | 解析器输出 AST，节点结构建议：`{ type: 'text' | 'bold' | 'italic' | 'color', value?, color?, children? }`。 |
| FR-23 | 未闭合标签在预览中的表现需产品决策，见 Q2；无论选哪种，编辑器侧必须给出可见提示。 |
| FR-24 | 预览更新做 100-300ms 防抖；源文本超过 20k 字符时关闭实时预览，改为手动刷新按钮触发。 |

### 5.6 粘贴与输入法

| 编号 | 需求 |
| --- | --- |
| FR-25 | 粘贴只取 clipboard 的 `text/plain`，丢弃 `text/html`；若粘贴的纯文本本身含合法 UBB，原样保留（提供 `stripAll` 开关可全清）。 |
| FR-26 | 输入法组合输入期间（compositionstart 到 compositionend）不执行任何标签插入或文本改写。 |
| FR-27 | 换行以 `\n` 原样保留，预览按 `\n` 分段渲染。 |

### 5.7 计数与校验

| 编号 | 需求 |
| --- | --- |
| FR-28 | 默认统计可见字符数（剔除标签与转义符），工具栏右侧显示"可见字数 / 上限"；可配置为统计源文本长度。 |
| FR-29 | 支持 maxLength。超限时按可见文本截断，不切断标签，保证标签仍成对。 |
| FR-30 | 组件需向上暴露"是否存在未闭合 / 非法标签"状态，供提交前校验。 |

### 5.8 数据与接口

| 编号 | 需求 |
| --- | --- |
| FR-31 | 受控用法：`props.value + onChange(sourceText, meta)`；非受控用法：`defaultValue` + 内部状态。 |
| FR-32 | meta 建议字段：`visibleLength`、`sourceLength`、`hasInvalidTag`、`hasUnclosedTag`、`selection {start, end}`。 |
| FR-33 | ref 暴露方法：`focus()`、`blur()`、`insertTag(name)`、`getSource()`、`getPlainText()`、`clear()`、`validate()`。 |
| FR-34 | 可配 props：`labels`（i18n 文案）、`theme`（light/dark）、`readOnly`、`disabled`、`placeholder`、`maxLength`、`showPreview`（是否显示预览区）、`previewMode`（分栏形态：左右 / 上下）、`mode`（'edit' | 'preview'，整体模式切换，见 FR-02）、`enabledTags`、`disabledTags`、`customTags`（自定义标签注册，见 5.10）。 |
| FR-35 | 草稿：可选 `autoSave`（localStorage，key 可配，默认关闭），防止误刷新丢内容。 |

### 5.9 移动端

| 编号 | 需求 |
| --- | --- |
| FR-36 | 工具栏触控区 ≥ 44px；取色面板改为底部抽屉。 |
| FR-37 | 移动端选区依靠 `selectionStart` / `selectionEnd` 计算，不依赖 contenteditable 相关选区 API。 |

### 5.10 自定义标签与插空

| 编号 | 需求 |
| --- | --- |
| FR-38 | 支持通过 `customTags` 注册业务自定义标签，注册项包含：`name`（标签名）、`label`（工具栏文案 / aria-label）、`paired`（是否成对，默认 true）、`render`（预览渲染方式）。注册后进入标签白名单，解析、包裹 / 解包、嵌套闭合修复、校验、可见字数统计全流程与内置标签一致。 |
| FR-39 | 插空 `[blank]...[/blank]`：无属性的业务标签，随组件交付默认注册配置。工具栏显示"插空"按钮；选中文本包裹为 `[blank]...[/blank]`，未选中插入空标签并将光标置于标签中间（行为同 FR-11）；幂等解包规则同 FR-12。 |
| FR-40 | 插空预览默认渲染为下划线空位：空标签渲染为固定宽度空位；包裹文字时按文字长度估算空位宽度、原文不显示。具体表现可由 `render` 配置，最终方案见 Q7。 |

### 5.11 独立渲染与 H5 复用

| 编号 | 需求 |
| --- | --- |
| FR-41 | 渲染能力独立入口：解析器（含 AST 类型定义）与只读渲染组件不依赖编辑器代码，通过子路径导出（如 `react-ubb/core`、`react-ubb/renderer`）单独引入，H5 页面不带入编辑器与取色库体积。 |
| FR-42 | 提供只读渲染 React 组件 `<UbbView source={string} />`，props：`source`、`customTags`（与编辑器同一注册结构）、`className`；编辑器内置预览与该组件共用同一解析与渲染实现，保证两端表现一致（就近闭合修复、非法颜色降级、插空空位等行为一致）。 |
| FR-43 | 提供纯函数 `parse(source): AST` 与 `toPlainText(source): string`（零 React 依赖）；AST 为纯 JSON 结构（见 FR-22），非 React 宿主可自行遍历渲染。 |
| FR-44 | 渲染组件内置轻量样式（类名统一前缀，同 NFR-08），样式随组件注入或提供独立 CSS 文件，H5 引入即用。 |

## 6. 非功能需求

| 编号 | 维度 | 需求 |
| --- | --- | --- |
| NFR-01 | 安全 | 不产出 HTML、不执行用户输入；渲染侧只做白名单标签 + 颜色正则校验；无 XSS 暴露面。 |
| NFR-02 | 性能 | 1000 字以内键入无感知延迟；1 万字首次解析 < 100ms；10 万字时输入不卡顿（可用预览降级策略）。 |
| NFR-03 | 体积 | 组件本体 gzip 后 ≤ 15KB（不含取色库）；引入取色库时按需引入单组件，整包 gzip 目标 ≤ 40KB；H5 仅引入 core + renderer（gzip 目标 ≤ 8KB）。 |
| NFR-04 | 兼容 | Chrome / Edge / Safari / Firefox 最近两个大版本；iOS Safari 15+；Android Chrome 90+；不支持 IE。 |
| NFR-05 | 可访问性 | 工具栏按钮具备 aria-label 与 aria-pressed；全键盘可完成加粗、斜体、选色；颜色对比度符合 WCAG AA。 |
| NFR-06 | 可维护 | TypeScript 严格模式，导出完整类型定义；解析器、包裹 / 解包逻辑、非法标签修复必须有单元测试。 |
| NFR-07 | 国际化 | 全部界面文案外置，至少支持中文与英文。 |
| NFR-08 | 样式隔离 | 不修改全局样式，使用 CSS Module 或内联样式，类名统一前缀，避免污染宿主页面。 |

## 7. 技术方案建议（概要）

### 7.1 模块划分

| 模块 | 职责 |
| --- | --- |
| Editor | textarea 输入 + 选区计算 + 工具栏 |
| Parser | tokenizer + 标签栈匹配，输出 AST（零依赖纯函数，独立入口） |
| Renderer | AST 转 React 元素（独立入口，供 H5 展示端单独引入） |
| ColorPicker | 可替换实现（复用库或自研） |
| i18n / types | 文案与类型定义 |

### 7.2 选区与撤销实现

| 方案 | 实现 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A（默认） | `selectionStart` / `selectionEnd` + `document.execCommand('insertText')` | 原生撤销栈完整保留，实现简单 | 依赖已废弃 API |
| B（降级） | 自行拼接字符串 + `setRangeText` | 不依赖已废弃 API | 撤销栈需自建 |

建议默认 A，对 execCommand 不可用的环境降级到 B 并启用自建 undo 栈。

### 7.3 解析策略

单遍扫描状态机优于正则：正则处理嵌套与交错闭合易回溯爆炸，且难以给出精确错误位置。

实现要点：遇到 `[` 尝试匹配已知标签名，用栈维护未闭合节点，关闭标签不匹配时按就近闭合处理并记录一条错误定位信息。

### 7.4 取色库取舍

| 方案 | 特点 |
| --- | --- |
| react-color | 功能全、社区成熟；需从具体入口按需引入（如 CompactPicker / Sketch），否则整包体积过大 |
| @uiw/react-color | 分包更细，体积更可控 |
| 零依赖 | 预设色板 + `input[type=color]`，能力够用但自定义取色体验一般 |

### 7.5 不选 Slate / Draft.js / Quill 的理由

三者面向富文本，数据结构为 HTML 或 Delta，做 UBB 需反向序列化，复杂度、体积、维护成本均远超本需求，且会把 contenteditable 的固有坑一并引入。

### 7.6 目录建议

```text
packages/ubb-editor/
  src/Editor.tsx
  src/Toolbar.tsx
  src/ColorPicker/
  src/core/          # parser / ast / types，零 React 依赖
    parser.ts
    transform.ts
    ast.ts
  src/Renderer.tsx   # UbbView 只读渲染组件
  src/types.ts
  src/locale/
  __tests__/

# 子路径导出：
#   react-ubb/core      → parse、toPlainText、AST 类型
#   react-ubb/renderer  → UbbView 只读渲染组件
```

## 8. 验收标准（可执行）

| 编号 | 验收标准 |
| --- | --- |
| AC-01 | 输入 "abc"，选中后点加粗，源文本为 `[b]abc[/b]`，预览为加粗 abc。 |
| AC-02 | 再次点击加粗，源文本回到 abc，预览样式撤销。 |
| AC-03 | 选区位于加粗内时选红色，得到 `[b][color=#FF0000]abc[/color][/b]`，预览同时加粗与变红，且不出现双层 color。 |
| AC-04 | 从网页复制带样式的段落粘贴，结果不含 HTML，也不含任何 UBB。 |
| AC-05 | 输入 `[b]` 未闭合，编辑器出现非法 / 未闭合提示，预览不吞后续文字，`validate()` 返回 false。 |
| AC-06 | 输入 `[color=red]x[/color]`，预览不应用颜色，组件不报错。 |
| AC-07 | 输入 5000 字并快速连续输入，无卡顿、光标不跳位。 |
| AC-08 | 中文输入法逐字上屏过程中，标签不被拆断、字符不丢失。 |
| AC-09 | 全键盘（Tab 进工具栏 + Enter）可完成一次加粗。 |
| AC-10 | Ctrl+Z 可正确撤回一次标签插入，光标位置正确。 |
| AC-11 | readOnly 状态下工具栏点击与快捷键均无效果。 |
| AC-12 | 组件输出满足字符集约定：仅允许白名单标签与合法颜色值，其余方括号按普通文本保留。 |
| AC-13 | 选中"答案"点击插空，源文本为 `[blank]答案[/blank]`，预览显示下划线空位；再次点击插空，源文本恢复为"答案"。 |
| AC-14 | 经 customTags 注册的自定义标签与内置标签走同一解析 / 校验 / 包裹链路：交错闭合可被就近修复，未闭合触发提示，`validate()` 返回 false。 |
| AC-15 | 点击"预览"切换后编辑区隐藏、整区只读渲染；切回编辑后内容与光标不丢失。 |
| AC-16 | H5 页面仅引入 renderer 子路径渲染同一份源文本，结果与编辑器内预览一致（含插空空位、非法颜色降级、就近闭合修复），且未引入编辑器代码。 |
